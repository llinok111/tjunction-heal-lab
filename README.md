# T-Junction Heal Lab

**一句话承诺**：对多分辨率拼接网格的 T-junction 做**零位移**修复——3 份解析语料共 **2,712 个 T-junction** 全部消除，修复后 **0 边界边 / 0 非流形边 / 0 绕序冲突**，表面积与体积相对原解析值误差 **≤ 5.4e-14**；检测 **11.121 ms**（中位，7 次）vs 仓库内 O(V·E) 基线 **301.949 ms**，**27.15×**。

Upstream: none

这是原创工具：把一个顶点落在另一三角形边内部（T-junction）当作可定位、可复检的缺陷。修复只**分裂已有边**并在三角形内部加一个质心点做扇形三角化，不移动任何原有顶点，因此被表示的曲面逐点不变；每条缺陷都带 `(vertex, triangle, edge, t)` 见证，浏览器与 node 共用 `src/core.mjs` 并比对 mesh hash。

## 怎么跑（零依赖）

```bash
node tools/gen-sample.mjs      # 重建 data/corpus.json + data/reference.json（固定输入，字节确定）
node bench/verify.mjs          # 44 条断言，全部打印实测值；exit 0 才算过
node bench/bench.mjs           # 1 冷启动 + 1 warmup + 7 次计时，写 bench/result.json
python3 -m http.server 4173    # 打开 http://localhost:4173 （three@0.169.0 由 importmap 固定）
```

`node --version` 需 ≥ 20；本次实测 v24.19.0。仓库不含 `node_modules/`，页面只从 jsDelivr 取固定版本 three。

| cube-k8 (2×2×2, 8×8 tiles) | 7,680 | 1,440 | 11,328 (+3,648) | 0 / 0 / 0 | 3.042e-14 | 4.796e-14 |
| box-k6 (2×1×3, 6×6 tiles) | 4,320 | 792 | 6,336 (+2,016) | 0 / 0 / 0 | 1.044e-14 | 6.961e-14 |
| plate-k5 (2×0.25×1, 5×5 tiles) | 2,928 | 480 | 4,176 (+1,248) | 0 / 0 / 0 | 4.774e-14 | 5.329e-14 |

- 三种独立检测器（网格加速、O(V·E) 基线、verify 里的叉积实现）对 2,712 条见证**计数完全一致，见证集合对称差 0**。
- 独立半边普查（排序字符串，不同数据结构）同样给出 0 边界 / 0 非流形 / 0 冲突；修复后再检测 T-junction **0**。
- 射线奇偶 oracle：**175,995** 个随机点（73,113 内 / 102,882 外，避开表面 0.5% diag）与解析盒成员关系 **0 mismatch**。
- 反例：删掉 +X 面后 112 条边界边、奇偶 oracle 抓出 **18,018 / 37,037** 个错分，证明 oracle 不是恒真。
- 尺度 1e-6 / 1e-3 / 1 / 1e3 / 1e6：修复后 T-junction 全 0、水密、面积/体积相对误差仍 ≤1e-12，结论按比例不变（容差按 bbox 对角相对化）。
- 修复确定性：同一输入两次 hash 相同（cube `0xa1a71739`），对已修复网格再跑为 **no-op**（+0 三角形）。
- 独立只读 verifier（自写暴力检测与半边普查，不 import `bench/oracle.mjs`）：pre-heal 1,440 → post-heal 0（1e-9 与 1e-12 两种容差）、Euler=2、原始 13,686 个坐标 word 逐位不变、verify 44/44 复算一致；它唯一的措辞 nit 是 5.329e-14 被写成 ≤5.3e-14，已改为 ≤5.4e-14。

**性能**（`bench/result.json`，7 样本；`cube-k8`，4,562 顶点 / 7,680 三角形 / 1,440 T-junction）：

| 路径 | cold (ms) | min | median | p95 | relSD |
|---|---|---|---|---|---|
| 网格加速检测 | 29.625 | 10.829 | **11.121** | 12.647 | 6.34% |
| `baseline/naive.mjs` O(V·E) | 320.540 | 298.825 | **301.949** | 314.125 | 1.91% |
| 检测+焊接+修复 | 34.530 | 21.255 | **22.806** | 26.939 | 7.89% |

- 提交文件的加速为 **27.15×**（`bench/result.json` 原始记录），冷启动 **10.82×**（含 JIT）。同机复跑比值为 **24.68× / 28.05× / 40.04×**：naive 基线尾部对 GC/CPU 噪声敏感，故只承诺「约 25× 量级且顺序稳定」，不用复跑值迁就文字。
- 修复计时是 9 个样本 × 每样本 10 次内循环、按单次折算；relSD 7.89% 来自每轮分配新三角形数组触发的 V8 GC（样本全量记录在 `bench/result.json`），未用缩小输入或改基线修饰。
- `bench/bench.mjs` 固定 1 冷启动 + 1 warmup + 7 次（修复为 9×10），p95 = 最近秩 `ceil(0.95n)-1`，relSD = stddev/median。

## 本轮创新

**B 档：T-junction 的零位移、可复算「曲面不变」修复。** 与常见的 ε-weld（移动顶点、且并不消除 T-junction）和重新三角化（改变曲面）不同：本工具只分裂已有边、只在三角形平面内加质心，把「修复后面积/体积逐位不变」写成断言（最大相对误差 5.3e-14），并用独立半边普查 + 17.6 万射线奇偶双重裁决；容差全部相对 bbox 对角，1e-6…1e6 五个数量级结论一致。以前这类缝隙通常靠肉眼或截图确认，这里每个 T-junction 都有可复检见证与可现场复跑的数字。

## 已知限制（诚实边界）

1. **只焊接完全相同的重复顶点（精确相等），不做 ε 吸附**。因此非重合裂缝（两侧顶点各有微小偏移）不会被修复；这是"不移动任何顶点"契约的代价。
2. T-junction 判定容差固定为 `1e-9 × bboxDiag`（`src/core.mjs` 的 `EDGE_EPS_FRAC`）。小于该容差的错位会被视为已共形，可能留下发丝裂缝；网格特征尺寸小于 1e-9·diag 时可能误判。有效尺度实测仅覆盖 1e-6…1e6。
3. 修复**不是最小三角形数**：每个被分裂的三角形加一个质心并扇形化，总三角形数增加 46.3%（6,912/14,928）；从角点扇形化在部分情形可少加几个面，但会引入退化/翻转分支，本版未做。
4. 语料是**轴对齐盒面**（解析面积/体积已知），不是真实扫描/CSG 资产；T-junction 都在平面内。曲面网格上算法应同样成立（分裂点仍在原三角形平面），但未用曲面语料实测。
5. 无头浏览器不可用，**未做真实 WebGL 截图**；页面证据是静态服务 200、importmap 存在、node/browser 共用 core 且 hash 可对账，不是截图。
6. 检测的网格 cell 只影响候选集大小，精确点-线段测试决定结果；性能数字依赖 cell=diag/18，换 cell 会改变耗时但不改变检出集合。

```

baseline/naive.mjs          O(V·E) 检测基线
data/corpus.json            生成物（477 KB）；data/reference.json 为 node 烘焙 hash
```
